# Сборка и проверка Android-приложения «Читалка»

В 0.1.7 добавлены бумажные книги: «Добавить книгу → Бумажная книга», ручная карточка, начало чтения и прогресс по страницам. Структурный тип и название с нумерацией вводятся вручную; поддержаны вложенные элементы, мысли, герои и цитаты. Проверены шесть групп сценариев и 15 проверок FB2, миграция и сохранение базы при повторной установке. В эмуляторе оставлен пример «Бумажная книга — проверка». На телефон эта версия не передавалась. Подробности: `Приложение/Android/_исходник/Проверки/Проверка 0.1.7.md` от корня проекта.

Версия 0.1.7. Дата: 31.10.2026.

В этой сборке импорт FB2 ограничен 64 МБ. При удалении приложения Android удаляет его внутренние данные; созданные записи предварительно сохраняйте командой экспорта. Markdown сохраняет текст записей, но не заменяет резервную копию всех данных приложения.

## Техническая основа

Прототип написан на Java с использованием штатных компонентов Android, WebView для подготовленного текста глав и SQLite для библиотеки и записей. Сетевых разрешений в APK нет. Исходная XML-разметка не исполняется как HTML: поддерживаемые элементы преобразуются, текст экранируется, внешние изображения не загружаются. DTD отклоняется.

Минимальный API сборки — 26, целевой — 36. Проверено только на виртуальном Pixel 7 с Android 16 / API 36; другие версии и реальные телефоны требуют отдельных испытаний.

## Повторная сборка

Обновление реального телефона по Wi-Fi описано в [отдельной инструкции](Обновление%20по%20Wi-Fi.md). Файл `Обновить на телефоне по Wi-Fi.cmd` собирает текущую версию и устанавливает её поверх прежней с сохранением данных; для первого запуска требуется сопряжение телефона. Готовность подключения POCO пока не подтверждена.

- [ ] 1. Убедиться в наличии SDK `D:\Android\Sdk`, платформы 36, Build Tools 36.0.0 и Java с компилятором. В текущем окружении используется JBR 25.0.2 из PyCharm.
- [ ] 2. Запустить `Собрать Android.cmd` или `tools/Build-Android.ps1`. Пути SDK, Java и временной папки можно передать параметрами сценария.
- [ ] 3. Проверить APK и `SHA256SUMS.txt` в `_приложение`.

Сборка выполняется локальными AAPT2, javac, D8, zipalign и apksigner. Загрузка зависимостей не требуется. Это сценарий сборки прототипа, Gradle-проект пока не настроен. Официальные сведения: [AAPT2](https://developer.android.com/tools/aapt2), [D8](https://developer.android.com/tools/d8), [выбор документов Android](https://developer.android.com/training/data-storage/shared/documents-files).

Windows-версия AAPT2 не открыла кириллицу в пути проекта. Сценарий копирует только папку `app` в `D:\Android\Build\Chitalka`, собирает там и возвращает APK в проект. Временные сборки не удаляются автоматически. Ключ для тестовых обновлений хранится в `D:\Android\Build\Chitalka\private\debug.keystore`; он не предназначен для публичного выпуска.

## Проверки

`tools/Build-Android.ps1 -WithChecks` дополнительно собирает отдельный тестовый APK в `.local/checks.apk`. После установки тестового и основного APK проверка запускается командой `adb shell am instrument -w ru.devimind.chitalka.checks/ru.devimind.chitalka.checks.ParserChecks`.

Обычный запуск выполняет 15 проверок FB2. Специальный режим `cleanup=true` дополнительно проверяет заранее созданные тестовыми действиями записи, иерархию и экспорт, после чего удаляет только эти тестовые записи. Этот режим требует соответствующего набора тестовых данных.

Для проверки интерфейса используется отдельный ReaderChecks: 12 проверок настроек, анимаций, разделов и сохранения. Параметр nimations=true выполняет два дополнительных испытания с промежуточными кадрами; cleanup=true удаляет только собственные записи из последнего протокола.

Для проверки карточки и миграции добавлены `LegacyBookSeed` и `BookChecks`. Первый сценарий запускается до обновления на тестовой базе версии 1 и записывает исходное состояние с собственными связанными заметками. После обновления второй проверяет перенос и создаёт отдельные тестовые книги. Его `cleanup=true` удаляет только собственные данные и восстанавливает сортировку. Эти сценарии предназначены для эмулятора с подготовленными данными.

Для обложек добавлены `CoverSeedChecks`, `CoverChecks` и тестовый провайдер изображений. Первый сценарий подготавливает собственную книгу и мысль на предыдущем APK. Второй проверяет обновление, обработку выбора изображения и отображение; `cleanup=true` удаляет только свою книгу, мысль и обложку. Провайдер включён только в тестовый APK, в приложение не входит.

Результаты текущего испытания — в [Проверке 0.1.6](Проверки/Проверка%200.1.6.md).
